# GPSM dependencies.
#
# Grouped by what you are actually doing, because the groups differ a lot:
# running MotionPrep on parameter files needs almost nothing, fitting on
# marker/skeleton files pulls in a real optimizer stack, and the simulator
# needs a GPU/display stack that will not work on Kaggle at all.
#
# On Kaggle, install with:
#     !pip install -q -r requirements.txt
#
# Kaggle images already ship numpy, scipy, torch, matplotlib and pyyaml, so
# that install is usually a no-op for the core group.

# --- Core: MotionPrep Stage 1+2 on parameter files (.npz, e.g. AMASS) ------
# All you need for the recommended Kaggle route. No torch, no body model, no
# per-frame optimization — Tier 0 is a reshape/resample, not a search.
numpy>=1.24
scipy>=1.10

# --- Training: MotionMamba --------------------------------------------------
# Install the torch build matching your CUDA version; on Kaggle torch is
# preinstalled, so leave the pinned line alone and let pip skip it.
torch>=2.0
safetensors>=0.4
loguru>=0.7
PyYAML>=6.0

# --- Fitting: MotionPrep Tier 1 on marker/skeleton files (.c3d, .bvh) ------
# This is the slow, optimizer-based path (~1.3 s/frame measured locally) and
# is NOT the recommended route for KIT — see doc/GPSM_Direction.docx sec. 4.
# Needed only if you deliberately choose to fit raw markers yourself:
#   - `c3d`     reads the marker files (adapters/markers.py wraps its Reader
#               directly; this is a different package from `ezc3d`)
#   - `smplx`   the differentiable body model the optimizer fits to the points
#   - `torch`   already listed above, doubles as the optimizer backend (LBFGS)
# Also requires the official SMPL-X model file (SMPLX_*.npz), downloaded
# separately from smpl-x.is.tue.mpg.de — registration-gated, not a pip package.
c3d>=0.6
smplx>=0.1.28

# --- Simulator and plotting (local desktop only) --------------------------
# pyrender/pyglet need a real OpenGL context, so this group does NOT work in
# a Kaggle notebook. Skip it there.
pyrender>=0.1.45
pyglet<2.0            # pyrender 0.1.x is incompatible with pyglet 2
trimesh>=4.0
imageio>=2.31
matplotlib>=3.7

# --- Development ------------------------------------------------------------
pytest>=8.0
python-docx>=1.1      # builds the files in doc/

# --- Not needed by anything currently run -----------------------------------
# ezc3d is imported by the legacy src/gpsm/utils/dataset.py loader only, which
# MotionPrep does not use (it reads .c3d through the `c3d` package above via
# its own LenientC3DReader). Left out; add it back only if you run that
# legacy path directly.
